# vrijeme.app — ecosystem update, Croatian redesign, any-location weather

## Context

vrijeme.app shows a forecast for one hardcoded place (Daruvar), in English, from a backend still on the pre-September Raptor
setup (CORS, absolute API URL, raw Open-Meteo JSON passed through). The go-raptor ecosystem has since shipped the fixes from
`~/dev/go/go-raptor/docs/2026-09-24-raptor-ecosystem-changes-prompt.md` (raptor v4.6.1, spa v2.1.0, logger v1.4.0, csrf,
requestid, secure, limiter, built-in health, `WithRemoteAddr`), and husak-dashboard was modernized and redesigned on top of
them last week. goopenmeteo v1.1.0 fixed parameter names and added sunrise/sunset, air quality and pollen.

Goal: a Croatian weather app useful to anyone in Croatia — weather for *your* location (GPS, a search, or one of 20 cities),
remembered between visits, with DHMZ warnings, air quality and pollen, installable on a phone, in a refined version of the
current blue look that follows the real sky.

**Decided with Kruno:** all four additions (place search + recents, DHMZ warnings, air quality + pollen, PWA); first visit is
a welcome chooser (the permission prompt only after tapping "Koristi moju lokaciju"); "living blue sky" visuals.

**Assumptions:** audience is people in Croatia, mostly on phones; UI is Croatian only (no i18n framework); forecasts work
anywhere, but place names, warnings and search are Croatia-only. Reuse husak-dashboard code and conventions wherever they fit
(paths below are `~/dev/go/husak-dashboard/...`).

### 2. API (all read-only, `lat`/`lon` validated: parseable, −90..90 / −180..180, else 400)

| Route | Action | Upstream / source | Cache |
|---|---|---|---|
| `GET /api/v1/forecast?lat&lon` | `Forecast.Show` | Open-Meteo forecast, `timezone=auto` | 10 min per key |
| `GET /api/v1/air-quality?lat&lon` | `AirQuality.Show` | Open-Meteo air quality | 30 min per key |
| `GET /api/v1/warnings?lat&lon` | `Warnings.Index` | Meteoalarm `feeds-croatia` (one feed) | 15 min |
| `GET /api/v1/places?q=` | `Places.Index` | Open-Meteo geocoding, `countryCode=HR&language=hr` | 24 h per query |
| `GET /api/v1/places/nearest?lat&lon` | `Places.Nearest` | embedded GeoNames dataset | — |

- **Key** = lat/lon rounded to 2 decimals (~1 km). The frontend rounds too, so precise coordinates never leave the device.
- **Caches:** port `app/services/cache.go` (`staleCache`: serves last good value on upstream failure, one fetch per key) and
  add a bounded `keyedCache[K,T]` (map of staleCaches, evicts least-recently-fetched past ~5000 keys). 502 only when nothing
  is cached.
- **Forecast model** (`app/models/forecast.go`, extends dashboard `app/models/weather.go`):
  - current: temperature, apparent, humidity, dew point, precipitation, code, cloud cover, pressure, wind speed/direction/gusts, visibility, UV, isDay;
  - hourly from the current hour to the end of the 7 days: temperature, apparent, precip probability and amount, code, wind, isDay;
  - daily, 7 days from today: min/max, code, precip sum and max probability, max wind/gusts, dominant direction, UV max, sunrise, sunset, daylight;
  - plus `timezone`, `elevation` and `fetchedAt`.
  Keep the `at()` helper and the "drop finished hours/days" logic.
- **Places** (`app/models/place.go`, `app/services/places_service.go`):
  - `data/hr-places.tsv` is embedded with `go:embed`: GeoNames HR populated places (PPL, PPLA*, PPLC; no PPLX sections), with name, lat, lon, admin1 and population. It's a few hundred KB, CC BY 4.0.
  - It's generated by `cmd/genplaces` (downloads GeoNames `HR.zip`) and committed.
  - Nearest place is a linear haversine scan. Beyond 15 km → no name (the frontend shows "Moja lokacija") and no county.
  - A 21-row county table maps the GeoNames admin1 code to a display name and Meteoalarm's `areaDesc`/EMMA_ID. Verify it against the live feed when building it.
- **Warnings:** port `app/models/warning.go` (`ActiveWarnings`, hr-HR info, cancels/updates, severity sort) and the service;
  the county comes from `nearest(lat, lon)`; lookahead 48 h (today + tomorrow); no county → `[]`.
- **Air quality:** port `app/models/airquality.go` (EAQI bands, six pollen types and their thresholds) and the service, keyed per location.
- **Upstream overrides for tests:** `APP_OPENMETEO_URL`, `APP_AIRQUALITY_URL`, `APP_GEOCODING_URL`, `APP_METEOALARM_URL`.

### 4. Location system
- `src/lib/data/cities.ts` — 20 cities, one per county (Zagreb covers Grad Zagreb + Zagrebačka):
  - Zagreb, Split, Rijeka, Osijek, Zadar, Pula, Slavonski Brod, Karlovac, Varaždin, Šibenik;
  - Sisak, Dubrovnik, Vinkovci, Bjelovar, Koprivnica, Čakovec, Požega, Virovitica, Gospić, Krapina.
- `stores/location.svelte.ts` persists the current location (`{kind: "gps" | "place", lat, lon, name}`) and up to 5 recents in localStorage.
  - `locate()` uses `getCurrentPosition` with a 10 s timeout and `maximumAge` of 15 min, rounds the position, then calls `/places/nearest`.
  - Denied, unavailable and timed-out locations each get a Croatian message.
  - When the Permissions API already reports "granted", GPS mode re-locates silently on open.
- `stores/weather.svelte.ts` loads forecast, air quality and warnings in parallel for the current location. Each fails on its own, so a warnings outage never blanks the forecast.
  - Stale-while-revalidate: the last forecast per location is in localStorage and painted instantly with "Ažurirano prije X min", then refreshed.
  - Polls every 15 min while visible, and refreshes on focus when the data is over 10 min old.
  - Shows an offline banner when `navigator.onLine` is false.
- UX:
  - **Welcome** (no stored location): the app name over the live sky, a large "Koristi moju lokaciju" button, then search and the city grid.
  - **Header place button** (place name ▾) opens the **location sheet**: a `<dialog>`, a bottom sheet on phones and centred on desktop. It holds "Moja lokacija", search (250 ms debounce, 2+ chars, keyboard navigable), "Nedavno" and "Gradovi".
  - **Pull-to-refresh** (custom component, touch only, at the top of the page; `overscroll-behavior-y: contain` disables the browser's reload pull) refreshes the data and re-locates in GPS mode. There is also a refresh affordance next to "Ažurirano…" for desktop.

### 5. Redesign — "living blue sky"
- `sky.ts` keyframes are retuned to stay in the current navy→teal family. Night is `#012a4a`-deep, day leans toward `#2c7da0`/`#468faf`, there's a faint warm horizon only around sunrise/sunset, and clouds grey it.
  - The sky is driven by the location's sunrise/sunset and current weather, with the same contrast clamp as the dashboard.
  - `theme-color` follows the top of the sky.
  - `prefers-reduced-motion` stops the precipitation layer and icon animation.
- Inter Variable with tabular numerals; translucent panels (the dashboard's `panel` and `text-lift` utilities, with a light blur on capable devices).
- The page, top to bottom: phones get one column; desktop gets two at max ~1100 px (hero, hourly and details on the left; days and air on the right).
  1. Header: place ▾, "Ažurirano prije 3 min" with refresh, and a GPS indicator.
  2. Warnings banner, coloured by level and always with an icon and text. It expands to the DHMZ description and shows the time window ("danas 14–20 h").
  3. Hero: animated icon, large temperature, condition, "Osjećaj 15° · ↑22° ↓9°", and the rain hint ("Kiša od 16 h").
  4. Hourly, the next 24 h: a horizontal scroll strip with a temperature curve and precipitation-probability bars (the dashboard's `hourly-chart.svelte` and `sparkline` ideas), and sunrise/sunset markers inline.
  5. 7 days: rows with icon, rain %, and a min–max range bar on a shared scale ("Danas", "Sutra", "pon 6. 10."). Tapping a day expands its hours, wind, UV and sunrise/sunset from the same hourly data.
  6. Detail tiles:
     - wind (direction arrow, gusts);
     - UV (band);
     - humidity and dew point;
     - pressure;
     - visibility;
     - sun (sunrise/sunset, day length).
  7. Air: an EAQI badge and pollen chips, showing only types with a level above "none" (outside the season it reads "Nema peludi").
  8. Footer: attribution for Open-Meteo (CC BY 4.0), DHMZ/Meteoalarm and GeoNames.
- `<title>` is "Daruvar · Vrijeme". Skeleton states, not spinners, on the first load without a cache.

### 6. PWA
- `static/manifest.webmanifest`:
  - name "Vrijeme", `lang` hr, `display` standalone, `theme_color`/`background_color` `#012a4a`;
  - icons at 192 and 512, plus a maskable one;
  - an `apple-touch-icon`, from a new `favicon.svg` (a simple blue sun/cloud mark), rendered to PNG with whatever is available (`rsvg-convert` or `magick`, or a bun script).
- `src/service-worker.ts` (SvelteKit built-in):
  - precaches `build` + `files` per version and deletes old caches;
  - navigations are network-first, falling back to the cached shell;
  - `/api` is never cached by the SW (localStorage holds the last forecast).
- New deploys: the version poll every 15 min; on `updated`, reload the next time the page becomes visible.
